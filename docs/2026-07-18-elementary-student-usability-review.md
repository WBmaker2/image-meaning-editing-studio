# 이미지 의미 편집실 초등학생 실사용 점검 및 개선 계획

- 점검일: 2026-07-18
- 점검 대상: 로컬 실행 화면 `http://localhost:3009/`
- 사용자 관점: 초등학교 4~6학년 학생이 교사의 긴 설명 없이 혼자 첫 사건을 끝까지 수행하는 상황
- 점검 범위: 시작 → 사용법 → 사건 선택 → 관찰 → 편집 → 효과 분석 → 비교 기록

## 1. 점검 방법

실제 브라우저에서 첫 번째 사건인 `비가 그친 운동장 벤치`를 선택하고, 화면 단서 4개를 찾은 뒤 편집안 선택과 효과·근거 연결을 거쳐 비교 기록까지 완주했습니다. 375px 휴대폰, 768px 태블릿, 1280px 데스크톱 화면도 각각 확인했습니다.

주요 확인 질문은 다음과 같습니다.

1. 학생이 다음에 무엇을 해야 하는지 바로 알 수 있는가?
2. 문장을 한 번 읽고 뜻을 이해할 수 있는가?
3. 처음 이미지와 바꾼 이미지를 쉽게 비교할 수 있는가?
4. 답을 빠뜨렸을 때 어디를 고쳐야 하는지 알 수 있는가?
5. 마우스뿐 아니라 키보드와 작은 화면에서도 조작할 수 있는가?

## 2. 잘 작동한 점

- 학습 흐름이 `관찰 → 편집 → 효과와 근거 → 비교 기록`으로 분명합니다.
- 준비된 그림만 사용해 업로드나 개인정보 입력이 없습니다.
- 버튼과 선택 영역이 휴대폰에서도 충분히 크고, 선택 상태가 색과 모양으로 구분됩니다.
- 처음 이미지에서 실제로 보이는 단서를 모두 찾게 한 뒤 편집으로 넘어가도록 막아 두어 관찰 활동이 형식적으로 지나가지 않습니다.
- 한 가지 편집만 정답으로 제시하지 않고 다른 선택도 비교하게 하는 학습 설계가 좋습니다.

## 3. 발견한 개선점

### FINDING-001 — 학생용 핵심 문장이 어렵습니다

- 중요도: 높음
- 확인 위치: 시작 화면, 사용법 3장, 사건 목록, 편집·분석·결과 화면
- 어려운 표현: `전달 효과`, `화면 근거`, `맥락`, `기준 이미지`, `편집본`, `프레임 밖`, `프리셋`, `타당한 편집`, `해석`, `단정`
- 학생에게 생길 수 있는 문제: 화면 조작은 할 수 있어도 질문의 뜻을 정확히 이해하지 못해 교사가 문장을 다시 풀어 설명해야 합니다.

개선 방향:

| 기존 표현 | 학생용 표현 |
| --- | --- |
| 전달 효과 | 전해지는 느낌과 뜻 |
| 화면 근거 | 화면에서 찾은 까닭 |
| 기준 이미지 | 처음 이미지 |
| 편집본 | 바꾼 이미지 |
| 프레임 밖 | 사진 밖 |
| 프리셋 | 보기 방법 |
| 해석할 수 있어요 | 그렇게 생각할 수 있어요 |
| 단정하기 어려워요 | 사실이라고 말하기 어려워요 |
| 타당한 편집 | 도움이 되는 다른 편집 |

### FINDING-002 — 휴대폰에서 두 이미지를 비교하기가 너무 깁니다

- 중요도: 높음
- 확인 위치: 편집·분석·비교 기록 화면의 375px 화면
- 현재 상태: `나란히 보기`가 기본이라 처음 이미지와 바꾼 이미지가 위아래로 쌓입니다.
- 학생에게 생길 수 있는 문제: 두 그림 사이를 긴 거리만큼 스크롤해야 하므로 무엇이 달라졌는지 기억에 의존하게 됩니다. 분석 질문도 두 그림 아래로 밀려납니다.

개선 방향:

- 600px 이하 화면에서는 `한 장씩 보기`를 기본으로 엽니다.
- 처음에는 `처음 이미지`를 보여 주고, 큰 전환 버튼으로 `바꾼 이미지`와 오갈 수 있게 합니다.
- 데스크톱과 태블릿의 나란히 비교 기능은 유지합니다.

### FINDING-003 — 답을 빠뜨렸을 때 안내가 구체적이지 않습니다

- 중요도: 높음
- 확인 위치: 효과 분석 화면에서 아무 항목도 고르지 않고 확인 버튼 선택
- 현재 안내: `아직 고르지 않은 항목이 있어요.`
- 학생에게 생길 수 있는 문제: 1~4번 중 어디를 빠뜨렸는지 다시 전부 찾아봐야 합니다.

개선 방향:

- 빠뜨린 번호와 이름을 직접 알려 줍니다.
- 예: `아직 고르지 않은 곳: 1번 달라진 점 · 3번 화면 속 까닭. 위에서부터 하나씩 골라 보세요.`
- 안내 문구를 읽는 즉시 어느 카드로 돌아가야 하는지 알 수 있어야 합니다.

### FINDING-004 — 키보드로 선택할 때 현재 위치가 잘 보이지 않습니다

- 중요도: 중간
- 확인 위치: 관찰 체크박스, 편집안, 분석 선택지
- 현재 상태: 마우스 선택 상태는 잘 보이지만 Tab 키로 이동할 때 선택 카드의 초점 표시가 약합니다.
- 학생에게 생길 수 있는 문제: 키보드나 보조 입력 장치를 쓰는 학생이 현재 조작 위치를 놓칠 수 있습니다.

개선 방향:

- 입력 요소가 `focus-visible` 상태일 때 레이블 전체에 굵은 외곽선을 표시합니다.
- 기존 선택 색상과 겹치지 않도록 청록색 외곽선과 바깥 여백을 사용합니다.

## 4. 구현 우선순위

1. 전 화면의 학생용 문장을 쉬운 말로 바꿉니다.
2. 휴대폰에서 한 장씩 비교하는 방식을 기본값으로 적용합니다.
3. 분석 단계의 누락 답변 안내를 번호와 이름으로 구체화합니다.
4. 키보드 초점 표시를 강화합니다.
5. `업데이트 내역`에 2026-07-18 개선 내용을 추가합니다.

## 5. 완료 기준

- 시작부터 비교 기록까지 학생용 핵심 문장에 위 표의 어려운 표현이 남지 않습니다.
- 375px 화면의 편집 단계 진입 시 한 장씩 보기와 처음 이미지가 기본으로 보입니다.
- 1~4번 답 중 일부를 비우고 확인하면 빠뜨린 번호와 이름이 표시됩니다.
- Tab 키로 체크박스·라디오 선택지를 이동할 때 레이블의 초점 외곽선이 보입니다.
- 기존 관찰 잠금, 결과 판정, 저장 기능이 그대로 동작합니다.
- 테스트, 타입 검사, 린트, 프로덕션 빌드가 모두 통과합니다.
